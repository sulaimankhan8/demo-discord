# Bottlenecks Identified

1. WebSocket connection fan-out limits per instance
2. Socket.IO per-client overhead under burst connections
3. Node.js event loop contention under heavy broadcast load
4. Single-instance architecture without distributed fan-out
5. Transport-level connection limits on the host instance

Degradation zone:

* ~600–650 messages/sec

Overload zone:

* > 650 messages/sec
* Connection failures increase rapidly
* ~37% virtual user failure
* System continues running without crashing

# Verdict

Attempt 37 demonstrates a significant throughput improvement compared with previous runs.

Outbound batching of Socket.IO messages dramatically increased the system's effective message throughput while maintaining extremely low latency. The system was able to sustain message rates exceeding 600 messages/sec with predictable degradation behavior under stress.

The primary scalability limitations observed in this run remain related to WebSocket connection fan-out and single-instance Node.js event-loop capacity rather than application logic, persistence, or message ordering mechanisms.

Further scaling improvements would require horizontal scaling techniques such as Redis-based Socket.IO adapters, distributed fan-out layers, or multi-instance sharding.
